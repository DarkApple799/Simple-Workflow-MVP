# 1 分钟演示视频脚本

> 目标：60 秒内让评审看到「Agent 循环 + 工具调用 + 报告产出」三件事。
> 建议用 **Windows 自带录屏 `Win + G`**（Xbox Game Bar）或 OBS；分辨率 1080p，终端字号调到 14~16 号。

---

## 一、录制前 5 分钟准备

```bash
cd code-review-agent

# 1) 确认密钥可用（能打印出模型名即正常）
python review.py scan examples --top 3

# 2) 先热身跑一次，确认 .env 有效、网络通畅（避免录制时卡住）
python review.py examples --out docs/sample_report.md --show 5

# 3) 清屏、放大字体，准备好浏览器标签页 http://127.0.0.1:8765
cls
```

| 准备项 | 说明 |
| --- | --- |
| 终端 | 建议 Windows Terminal，字号 16，窗口 120×32 |
| 编辑器 | 提前打开 `examples/buggy_service.py`（展示"故意写坏的代码"） |
| 浏览器 | 提前启动 `python webui.py --port 8765` 并打开页面（第二个终端窗口） |
| 备用方案 | 若网络不稳，用 `--offline` 演示（规则引擎 0.2 秒出报告），口播改为"离线规则模式" |

### 完整口播稿（约 240 字，正常语速 ≈ 60 秒）

> 这是我用 Python 标准库加 LLM 原生 API 实现的代码审查 Agent。它先跑确定性规则拿到事实，再让大模型通过工具调用去核实和补充，最后产出报告。
> 先看规则引擎：AST 加正则，二十五条规则，不联网，两秒扫完，能定位到具体文件和行号。
> 接下来是 Agent 循环：它先做预扫描，然后自己决定调用哪些工具——列目录、读文件、单文件深挖；观察结果回灌后再推理，最多八步，最后用 submit_review 这个终止型工具提交结构化结论。
> 报告按严重程度分级：硬编码密钥、shell 注入、eval、可变默认参数都定位到了行号，并给出修复写法。
> 同一个 Agent 也有零依赖的 Web 界面，用标准库 http.server 实现，不需要安装任何东西。
> 项目带一百零二个单元测试，覆盖重试降级和边界情况，全部通过。

## 三、拍摄要点

1. **先跑通再录**：在线模式一次约 15~25 秒，正好填满"工具调用滚屏"的画面，不要剪掉——那是 Agent 在工作的证据。
2. **画面要有对比**：`examples/buggy_service.py` 里那一行 `os.system("ping -n 1 " + host)` 可以在最后 2 秒快速闪一下，让评审看到"报告说的就是这里"。
3. **别念代码**：口播只讲"它做了什么、为什么这样设计"，细节交给屏幕上的报告。
4. **失败也不慌**：如果录制时网络超时，程序会自动降级成规则报告，你可以顺势说："网络异常时它会自动降级，仍然给出规则报告，这也是设计的一部分。"
